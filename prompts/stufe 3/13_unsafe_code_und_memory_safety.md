# Audit 13 — Unsafe Code and Memory Safety

Date: 2026-10-25. Scope: production Rust sources in both libraries, daemon entry points, wire decoding, arithmetic, allocation and chain traversal. Base HEAD: `d5be41f4e8a9662dffb5170b629191a950aab922`, with existing/concurrent working-tree edits. Audit only.

## Findings

- **A13-01 / P2 — Median calculation overflows before division.** `crates/humoco-sim-core/src/quota.rs:107`: `(left + right) / 2` panics in the checked build for `[u64::MAX, u64::MAX]`; wrapping arithmetic would produce the wrong median. Reproduced against the actual compiled library. Production calls exist in `humoco-node/src/network/manager.rs:2383,2389`. Read rates derive from peer-declared `u64` EMAs; `ema_to_daily_rate` permits values whose pairwise sum exceeds `u64::MAX`. No full signed-peer/QUIC reproduction was executed, so a remote daemon crash is **not** established.
- **A13-02 / P3 — Public day conversion has unchecked multiplication.** `crates/humoco-sim-core/src/quota.rs:71`: `ByteYears::from_ttl_days(u64::MAX)` panics in the current checked build, reproduced. The source expression can wrap under unchecked arithmetic. The current daemon's normal root-millisecond-to-seconds path does not demonstrate this reachability. `SimTime` addition (`types.rs:101–110`) similarly lacks an overflow contract and should be reviewed during the same boundary cleanup.
- **A13-03 / P3 — Unsafe prohibition does not cover the main binary crate.** Both libraries and `src/bin/cluster_sim.rs` declare `#![forbid(unsafe_code)]`, but `humoco-node/src/main.rs:1` does not. Crate-level library attributes do not enforce the separate executable crate. No actual unsafe block was found there; this is a future-enforcement gap.

Checked protections: no unsafe block, pointer transmutation or raw-memory API found in the inspected first-party production sources. WireHeader and LockEntry144 decode fixed arrays through safe little-endian operations; 512 actual header/record roundtrips passed. `network/framing.rs:829–865` checks the message limit before allocation, caps both standard and sync frames at 64 KiB, uses bounded reads and verifies exact body length. The inspected chain/tree loops are iterative; no unbounded recursive proof-chain descent was found. This is source inspection, not a proof for all dependencies or every possible parser input.

Validation: `cargo test --offline --workspace --lib` passed **237 tests**. Full `cargo test-std --offline` failed to compile the unrelated `quorum_assembly_tests.rs:735` field access (see Audit 15). Miri is not installed in the inspected toolchain; no Miri/UB run is claimed. `mimalloc`/`libmimalloc-sys`, `ring` and transitive `zerocopy` appear in dependencies: absence of first-party unsafe code does not establish that the entire executable/dependency graph is pure safe Rust. No direct bytemuck/zerocopy decoding integration was found.

Final shared standard validation: `timeout 180s cargo test-std --offline --no-fail-fast` exited124. Completed targets: **417 passed,1 failed,14 ignored**; unfinished `status_reconciliation_tests` is excluded from these totals. The failure was `test_valid_signatures_for_wrong_request_or_tls_context_never_form_quorum_wire` at `phase11_wire_level_adversarial_tests.rs:1811`: one actual send versus two expected; HTTP503 rejected the request. This is a failed test, not evidence of an accepted forged quorum. The original E0609 field access was repaired concurrently before this rerun. The full baseline remains incomplete and non-clean.

## Integrated fix plan

1. **A13-01:** calculate even medians using a `u128` sum followed by division and checked narrowing, or `low + (high - low) / 2` after sorting. Preserve floor-rounding. Add MAX/MAX, MAX−1/MAX, zero and odd-length controls. Exercise `effective_network_medians` with admitted extreme read EMAs; then add a signed real-QUIC test before declaring receiver protection.
2. **A13-02:** choose and document a checked-error or saturating boundary contract; use checked day-to-second multiplication and explicit safe `SimTime` arithmetic. Test maximum values and the last non-overflowing day. Do not silently saturate a value that changes accounting without an explicit policy.
3. **A13-03:** add `#![forbid(unsafe_code)]` to `main.rs` and keep the rule on every executable/library target. Verify all targets compile; retain dependency exceptions as explicit scope, without introducing transmutation libraries.
4. Repair the independent standard-suite build failure, then run library, wire/framing and full standard tests. Optional later validation: install a supported nightly with Miri and run `cargo +nightly miri test -p humoco-sim-core --lib` on compatible tests. Miri results cover executed paths only; external allocator/OS/QUIC behavior needs separate evidence.
